# Q-086 — the DCF is an FCFE model, and now says so

**Date:** 2026-10-17 · **Kind:** migration note.

**Live valuation figures:** no change. Production net debt was already 0 for every ticker.

**What changes:**
- the model's name and the discount rate's label;
- banks and insurers are refused;
- the dead net-debt code is removed.

## What Q-086 asked

Q-086 asked whether the `netDebt = 0` fallback ever fires on the live universe, and whether the UI flags it. It fires for **every ticker**, not as a fallback but as the main path:

1. **The balance sheet is empty.** Yahoo's `balanceSheetHistory` has carried no fields since November 2024. Each row has only `endDate`; this was measured on AAPL, JPM, NEE and XOM on 2026-10-16, and yahoo-finance2 itself warns about it.
2. **Every field read as 0.** The builder's `longTermDebt ?? 0`, `shortLongTermDebt ?? 0` and `cash ?? 0` therefore produced **net debt = 0** for every name. The Phase-14 net-debt fix was inert in production.
3. **The UI caveat was right only by accident.** The Valuation tab said the DCF "ignores net cash/debt adjustment", which was true for that reason, not by design.

## A second problem

`fcf0` is Yahoo's `financialData.freeCashflow`, which Yahoo labels **levered** free cash flow: it is after interest, so it is cash available to equity holders.

The code discounted that cash flow at a "WACC" and then, by design, subtracted net debt. That is the FCFF→equity bridge, applied to a cash flow that had already paid the debt holders. If the bridge had worked, it would have counted debt twice. Because it was inert, the live valuation was actually **levered FCF discounted at the user's rate**, which is an FCFE valuation labelled as FCFF.

## The change

| | Before | After |
|---|---|---|
| Model | described as FCFF with a debt bridge | **FCFE**: levered FCF discounted at the rate you set; no bridge (Damodaran 2012, ch. 14) |
| Rate label | "WACC" | "Discount rate (cost of equity)" |
| Net debt | built from an empty balance sheet, 0 for every ticker | not computed; the dead code is removed |
| Banks, insurers, capital-markets and mortgage firms | a per-share "value" from their FCF | **refused**, with the reason: their debt is operating capital, so cash flow after debt is not a valuation base (Damodaran ch. 21). Credit Services, such as payment networks, keeps its DCF. |
| UI caveat | "DCF ignores net cash/debt adjustment … upgrade for production" | explains FCFE and why no bridge applies |

**The numbers do not move in production**, because net debt was already 0. In the test fixture, which still carries a balance sheet Yahoo no longer sends, every per-share value rises by exactly $15, which is 15e9 of the fixture's net debt divided by 1e9 shares. The composite bands do not move.

## Not done here

- **The discount-rate default (9%) is unchanged.** It is now labelled as a cost of equity, which needs an assumption review (accountant gate).
- **The empty balance sheet still feeds the Financials tab's balance table**, which renders "—" throughout. Moving to `fundamentalsTimeSeries` is Q-087's data-gap question.
- **The DCF anchor feeds the adaptive buy/sell zones** shown to users. That surface is close to the regulated-advice line (Q-083) and is unchanged here.
