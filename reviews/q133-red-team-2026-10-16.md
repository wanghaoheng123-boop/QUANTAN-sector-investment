### F6. MEDIUM: the re-arm's user-visible description is false, and no decision record says why re-arm was chosen over halt or cooldown (needs ledger row)

- **Where:**
  - `lib/backtest/core.ts`, the breaker branch: `state.peakEquity = currentEquity(state)` after `closePosition(…, 'max_drawdown', …)`.
  - `lib/backtest/strategyDescription.ts`, the `Drawdown Breaker` row in `ENGINE_RULES`, rendered in the Strategy Rules grid.
- **False sentence (product copy):** "The peak then resets to the equity after that exit, so later positions are measured from where they start."
  - The peak is a mark-to-market high-water mark (`eq = currentEquity(state, signalPrice); if (eq > peak) peak = eq`), updated every bar after the reset.
  - Only the first position after a trip starts at the reset peak, less its entry cost. Every later position is measured from the running high since the trip, including open gains it never realized.
  - Example: position 2 rises 30 % and closes flat; position 3 is then measured from position 2's intra-trade high, not from where position 3 started.
  - The same sentence is in the code comment ("The guard now measures later positions from the equity they start with").
- **Overstated sentence** (commit and note): "after one trip every later position would have closed one bar after entry". This holds only while post-exit equity stays at least the cap below the old peak. An exit fill that gaps up past that line escapes it.
- **Policy point:**
  - Before the fix, the strategy kept opening positions and closing each one bar later, a cost drain rather than a halt, so the fix is an improvement.
  - Re-arm with no cooldown is still a choice. The next BUY can fill one bar after the breaker's own fill: the breaker fills at open `i+1`, and a BUY observed at close `i+1` fills at open `i+2`.
  - Halt and re-arm-after-cooldown are the obvious alternatives. CLAUDE.md's definition of done asks for a decision note when such a choice is made, and the migration note only argues that the old behaviour was a bug.
- **Verified:**
  - Code reading of the branch order: time exit, then breaker with mark-to-market peak update, then signal.
  - Mutation M1 (delete the re-arm line) fails `engineExits.test.ts > does not close the NEXT position one bar after entry`. So the fix has an effect, and the scripted `vi.mock('@/lib/backtest/signals')` binds to `core.ts`'s `./signals` import: the real classifier never BUYs a flat series, so that test could not pass without the mock.
- **Fix:**
  - Copy: "The peak then resets to the equity after that exit; drawdown is measured from the highest equity reached since."
  - Record the re-arm-versus-halt-versus-cooldown choice in a decision note.
- **Retracted from an earlier draft:** two claims were withdrawn.
  - "From a fresh peak a single 15 % position cannot trip the 25 % cap" is wrong. The peak ratchets up on open gains, so a position that roughly triples and then falls back below entry can trip it with no prior realized loss.
  - "The pre-fix behaviour was effectively a halt" is wrong, for the reason given above.
