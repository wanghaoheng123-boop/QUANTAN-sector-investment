### B2 — The headline claim says every consumer shows a failure; four live consumers do not, and the guard passes all four
Commit title: "every consumer shows it". Q-140 resolution: "a derived consumer guard found 4 blind consumers. All fixed."

1. **`app/page.tsx:76`, `/api/prices`.**
   - `res.json()` is called with no `res.ok` check. The route's 500 body `{degraded:false,error:{…}}` parses, so
     nothing throws, no toast appears, and old prices stay up.
   - This is the defect fixed on heatmap/commodities in this same commit.
   - **Proven by mutation:** changing `if (res.ok)` at `app/page.tsx:176` (the `/api/briefs` fetch) to
     `if (res.status < 400)` makes the guard fail with "app/api/prices … consumers never look: ['app/page.tsx']".
     The `/api/prices` consumer passes only because of a `.ok` read on a *different* route's response.
2. **`app/page.tsx:174-185`, `/api/briefs` on a non-2xx response** (429 at 6 req/min/IP, or the 502 catch).
   - `if (res.ok) {…}` has no else branch.
   - **Rendered in jsdom** with `/api/briefs` returning 429: the header reads **"Live from Yahoo Finance · 0
     articles"**, the page shows "No news available at the moment", and there is no failure notice.
   - Q140-1 claims this exact "quiet news day" is fixed.
   - The guard models one failure mode per route (`degraded`), so the 429/502 path of a 2xx-degraded route is never
     checked.
3. **`app/stock/[ticker]/page.tsx:302-303`, `/api/options`.**
   - `.then(r => r.json())` has no `r.ok` check. The 502 body has no `calls`, so the tab renders (`:561-563`)

4. **`components/stock/quantlab/hooks/useQuantLabFundamentals.ts:75-77`, `/api/analytics`.**

- **Fix:** give each of the four sites its own failure state and pin each with a render test. In the guard:
  - check `.ok` within the same expression or statement as the route literal, not anywhere in the file;
  - require every consumer of every route to also handle non-2xx, since every route has a 429 path.
- **Wording:** extend the CANNOT-DO. It is not only "a read in an imported module"; a read of a *sibling fetch in the

### H2 — Two EXEMPT reasons are false, and both routes fail silently
- **Where:** `fail-closed-routes.test.ts:80-81`. Both say "Reads committed fixtures, no network upstream."
- **Fact:** `app/api/conditional-vol/[ticker]` calls `fetchGarchForecast` and `app/api/regime/[ticker]` calls
  `fetchHmmRegime`. Each fetches `${QUANT_FRAMEWORK_URL}/garch|/regime` and swallows failure in a literal
  `catch { /* fallback */ }` (`lib/quant/garchClient.ts:90`, `lib/quant/regimeHmmClient.ts:62`).
- **Run with `QUANT_FRAMEWORK_URL=http://quant.test` and fetch rejecting:**
  - conditional-vol called `http://quant.test/garch/AAPL` and answered **200** with `"model":"GARCH(1,1)"`, although
    the forecast is EWMA.
  - regime called `http://quant.test/regime/AAPL` and answered **200** with `{"Bull":0.65,…,"source":"rule-fallback"}`.
  - Neither answer carries `degraded`.
- **Impact:** low today, since neither route has a UI consumer. But the exempt list is the detector's denominator, and
  a false reason is how a route that fails silently gets past it.
- **Fix:** move both into `CASES` with the `env` set (as done for ML), emit `degraded` on fallback, and correct the
  `model` label.

- **Where:** `app/api/ma-deviation/route.ts:138-147`. A degraded board skips the module cache and sends `no-store`.
